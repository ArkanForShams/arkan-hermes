# Marketing Websites for Shams's Ventures

Shams commissions bilingual (EN/AR) marketing sites for KSA ventures. Current active
project: AutoLead.sa vehicle-leasing site in
`~/hermes-workspace/marketing/autolead-website/`. Layout: build_pages.py generates the
9-page site; build_vehicle_studio.py builds vehicle-studio.html (the PRIMARY vehicle
page — real per-model photos); build_vehicle3d.py keeps the legacy 3D showroom
(vehicle-3d.html) as fallback; styles.css + site.js are shared; real vehicle photos live
in assets/vehicles/ (fetch_vehicle_photos.py refreshes them + credits.json).

## Brand-first rule

NEVER invent brand assets (logo, colors, fonts) when a real identity may exist — ask for
the logo file FIRST, or build in deliberately neutral tones until it arrives. A guessed
brand gets reskinned later anyway (this cost a full re-skin once: invented gold monogram →
real red wordmark arrived → every page restyled). When the real logo exists, copy it into
`assets/` and reference it from site.js so every page inherits it.

## Standing content rules (Shams-verified preferences)

- Design taste (v4 system in styles.css): LIGHT, elegant, professional — ivory bg
  `#f6f5f2`, white cards with soft shadows, ink `#171a1d`, AutoLead red `#e63946`
  accent, Nunito. Never reintroduce a dark theme site-wide; the ONE deliberate dark
  element is the photo/3D stage inset (cars read best against a dark studio floor),
  framed inside the light page.
- Placeholder prices/tariffs are ALWAYS flagged on-page (`.draft` badge class) AND noted
  in the delivery message. Never present invented numbers as final.
- Anchor pricing to a live market study (web_search competitor tariffs) and state the
  source and positioning quartile on the page. Never invent prices from thin air.
- Bilingual EN/AR is the default assumption for KSA sites: real RTL tree (dir=rtl,
  logical CSS properties, no letter-spacing/uppercase on Arabic, LTR phone numbers inside
  Arabic text), a working language toggle, and professional Arabic copy — not literal
  machine translation.
- Show customers the math: line-by-line price breakdowns (base + insurance + maintenance
  + registration + assistance = total, VAT stated separately) are a feature, not clutter.
- Keep a DRAFT-tariff discipline even in calculators: engine factors print on the page.

## Theme overrides (mid-build theme changes)

When the user requests a theme change mid-build (e.g. 'use professional and elegant
theme rather dark'), apply it as a clearly-marked override block appended to the
shared stylesheet (`site.css`), and keep the original dark hero/section colors as
scoped exceptions — a flat search-and-replace of every background produces invisible
text somewhere. Scope nav colors to both states (transparent-over-hero vs `.scrolled`
glass) so links stay readable on dark hero AND light scrolled backgrounds. Re-verify
contrast on every surface the override touches (nav over hero, footer social links,
nav chip) with a browser vision pass — element snapshots do not show color contrast.

## Build & verification procedure

1. Pages are generated by build scripts (build_pages.py pattern): shared HEAD/FOOT
   templates + per-page bodies + injected data via json.dumps into a `var ALDATA={...}`
   script tag. Rebuild after editing: `python3 build_pages.py`.
2. Verify structure: HTMLParser tag-balance check over every page (void-tag set:
   meta/link/br/hr/img/input/source/path/circle/rect/stop).
3. Verify JS: extract embedded script, `node --check` it. Format-string (%-templating)
   breaks on JSON data with braces — inject data via string concatenation of json.dumps,
   not % formatting.
4. Serve and curl-check every page + assets for 200 before presenting links (links and
   tunnels: see the local-site-sharing skill).
5. Commit every milestone to the archive repo immediately — Shams treats sites as
   inheritable assets.

## Vehicle showroom (vehicle-studio.html primary, vehicle-3d.html fallback)

- Photo studio is the customer-facing default: real per-model photos on a dark stage
  with red floor glow, paint swatches applied as CSS filters over the photo, per-photo
  credit line on stage, photo thumbnails in the price table.
- Real vehicle photos: `fetch_vehicle_photos.py` searches Wikimedia Commons by
  make+model with fallback search terms, saves into `assets/vehicles/`, writes
  `credits.json`; keep the on-page credit line (CC licenses). Swap in AutoLead's own
  fleet photography the same way when available.
- VERIFY IMAGES BY EYE (vision_analyze per car) before shipping: correct model, no
  damage/rally/heavily-modified shots. And never trust HTTP 200 alone — a vehicle-image
  CDN with a dead demo key returned 200 + an identical "car under cover" placeholder
  for EVERY model (identical file sizes/md5 were the tell). Check content and
  file-identity, then eyeball.
- After any build, grep the built HTML for EVERY script include the page needs. The 3D
  page once loaded three.min.js but NOT three-scene.js (which holds the scene code) —
  blank stage, no build error, user-reported. Tag-balance and node --check do not catch
  a missing `<script src>`; verify includes explicitly.
- Keep a WebGL failure guard in the 3D scene: try/catch around renderer construction
  that swaps in a visible notice; specs/calculations must still render when 3D fails.
- In the scene, keep ONE THREE.Group for the car and swap its children on selection —
  orphan group references (a `carSlot`/`car` mismatch) silently render nothing.
